# 社員ロール失効の監査

ローカルDBの `sauna_app` には監査表の照会・施設・利用者IDへの INSERT だけを付与し、失効時刻はDBが設定します。マイグレーション適用時は旧権限を取り消してから再付与します。普段のローカルDBでは閲覧は既存のDB管理者に限ります。下記の隔離検証では専用の閲覧ロールを使います。監査表は施設・利用者・照会の各Sauna内IDと失効時刻を記録します。

## 閲覧権限と保持の方針案

対象は社員の施設ロール失効イベントです。照会IDは失効処理と監査行を対応付けるために使います。閲覧用途でも公開するのはこのID、施設ID、利用者ID、失効時刻の4項目に限定します。

| 役割 | 権限と条件 |
| --- | --- |
| API実行ロール | 照会・施設・利用者IDを追記。失効時刻はDBが設定する。 |
| 指名された監査担当 | 承認された施設の4項目を閲覧。閲覧理由と対象施設を記録し、権限に期限を設ける。 |
| 削除担当 | 承認済みの削除を専用の保守経路から実行し、件数を確認する。 |
| DB所有者 | スキーマと権限の管理を担当する。通常の監査閲覧には専用ロールを使う。DB所有者は監査表も変更できるため、管理者操作は別途記録する。 |

保存期間の候補は失効から90日です。失効の問い合わせと障害調査に使える期間を確保し、社員と施設の対応を保存し続ける期間を抑えるための提案です。期間、閲覧担当、削除の承認者、バックアップの保持、調査中の削除保留を本番運用担当が確定するまでは、自動削除を無効にします。30日・1行は下記の合成検証に使う値です。

## 削除手順案

1. 保守担当は承認済みの適用日数と1回の上限を確認します。調査などの保留がある場合は、その対象を安全に除外できるまで実行を保留します。
2. 対象環境を確認し、次の1バッチの候補件数をプレビューします。表示上限はバッチサイズなので、表示件数は期限切れ全体の件数とは限りません。実行承認には対象環境、基準日時、日数、上限、候補件数を記録します。
3. 承認後、承認に記録したUTCの基準日時を使用し、そこから指定日数を引いた時刻より厳密に古い行を失効時刻順に1バッチだけ処理します。上限到達、並行ロック、タイムアウト時は件数と状況を確認し、処理を続ける場合は再度プレビューします。
4. 実行者、承認参照、実行時刻、削除件数、結果を保守記録に残します。監査行の利用者IDや照会IDのエクスポートは作成しません。

本番の閲覧認可、操作履歴、削除保留、バックアップからの失効済みデータの扱いは [Issue #36](https://github.com/sauna-studio/sauna-api/issues/36) の残作業です。以下の隔離検証では合成データを使用します。

本番適用の前に、運用責任者が保存期間と承認者を確定し、閲覧権限の付与・取消、調査保留中の削除拒否、バックアップ復元後の期限再適用を検証します。復元した環境を業務に戻す前に、削除済みの行が再公開されないことを確認します。

## ローカル検証

保持処理の検証には、ネットワークを公開しない隔離PostgreSQL 18を起動するAtlasリプレイを使います。`migration_base` に信頼済みのmainのコミットSHAを設定してから実行してください。

```sh
.venv/bin/python scripts/migration_ci.py --runtime apple --base "$migration_base"
```

リプレイは専用の `sauna_audit_sandbox` DBに合成データだけを登録します。ローカルのプレビューと削除はそれぞれの実行時刻で期限を計算します。保持SQLは対象DB名・所有者・専用マーカーを確認し、プレビューで行を残すこと、期限切れの行を失効時刻順に指定件数まで削除すること、新しい行を残すことを検証します。最古の行を別トランザクションがロックしている間はその行を飛ばし、ロック解除後の再実行で削除することも確認します。既存の開発DBである `sauna_atlas_replay` と同じ名前のDBでも、保持SQLが実行を拒むことを隔離環境で確認します。

隔離リプレイの閲覧ロールは、施設を固定したビューを通して、同じ利用者の別施設の行を除外します。基表の参照、書き込み、他ロールへの切り替え、開発DB名を使った接続の拒否も検証します。

Atlasの隔離リプレイは、制限されたアプリ接続で監査の INSERT 成功と SELECT・UPDATE・DELETE・TRUNCATE と失効時刻指定の拒否を確認します。Swift全体の使い捨てDBでは監査の照合・片付けに必要な SELECT・DELETE をテスト用に追加します。起動スモークは `--restrict-employment-audit` を指定して INSERT のみに戻せます。
