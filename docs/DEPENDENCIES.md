# API dependency catalogue

ユーザー指定のblindlog-api参照と追加ライブラリを、将来用の未使用分も含めPackage.swiftへ宣言する。Swift6.4/compiler policy・既存実装のtarget構成は維持し、解決revisionをPackage.resolvedへ固定する。未使用dependencyのSwiftPM警告は宣言を削除して隠さない。

## 現在使用する基盤と将来用の宣言

Baseline PR #43 selects Hummingbird, OpenAPI Generator (build plugin), Runtime/adapter, PostgresNIO, Crypto and Logging. NIO/HTTPTypes/ServiceLifecycle are also transitively linked through that foundation. The dependency catalogue declares additional packages without selecting all their products. Stacked authentication PR #44 explicitly uses WebAuthn, new CBOR, the swift-postgresql PostgresNIO trait/rendering bridge, swift-sql/ISO and NIO/HTTPTypes/ServiceLifecycle. No old SwiftCBOR parser remains in the locked graph.

blindlog参照のCurrency型も将来の通貨型利用に備えて宣言するが、現行のISO通貨文字列/minor整数契約は変更しない。

ArgumentParser、HummingbirdAuth、PostgresKit、JWTKit、Cloudflare、HummingbirdPostgres、Valkey、SwiftOTel、UUIDV7もユーザー指示で先に宣言する。宣言だけでclient・exporter・認証・外部送信を有効化しない。JWTやGoogleログインをPasskeyの代替認証として追加しない。API key・外部秘密鍵が必要になる処理は実装開始時にユーザーへ確認する。

The fork passed 65 strict native and exact-snapshot Apple-container/Linux tests plus its latest-head GitHub review/CI gates. These are scoped checks, not validation of every unused library feature. ## Cold-start process smoke investigation

[Bug #45](https://github.com/sauna-studio/sauna-api/issues/45), a sub-issue of #34, records a smoke-harness failure during catalogue verification. Commit 8617e67 failed the process readiness check after 3.161s in push run 41231665693, while its same-head PR run 41231670743 passed (1.746s for that test). Build succeeded; the old harness exhausted 100 sleeps of 30ms and reported both early exit and readiness exhaustion as serverDidNotStart. The original window was tight, but the later fifteen-second failure below shows that extending it does not explain the intermittent behavior. A production startup defect or port-contention cause has not been confirmed.

The test harness now uses a monotonic nominal fifteen-second readiness deadline. Each real HTTP probe has 300ms request/resource limits, so an in-flight probe can add a small bounded deadline overshoot. Early child exit reports only its exit status; readiness timeout and parent cancellation remain distinct. Normal startup stdout/stderr go to the null device instead of unread pipes, and failure cleanup targets only the process created by that test. Production API/configuration, random port selection and database contents are unchanged.

Regression tests cover readiness arriving after 3.3s (beyond the old window), bounded unavailable readiness with an elapsed-time ceiling, early exit metadata and cancellation propagation. The existing real executable health/version and graceful SIGTERM checks remain. Focused native smoke verification originally executed six tests. At 387a0da, push CI 41233233736 passed all 42 tests, while same-head PR CI 41233238365 timed out after 15.009s on real-child health; all four new helper regressions passed. The underlying Linux failure remains open. The earlier failed jobs are preserved as evidence rather than blindly rerun to hide the failure.

The next diagnostic-only harness change reports closed transport categories, bounded HTTP status, Linux selected-port listener presence, owned-child thread count and expected-executable identity. Listener presence alone does not establish ownership. Error descriptions, URLs, port values, response bodies, child output and environment values are excluded. A synthetic-error regression checks that private userInfo does not reach diagnostic metadata. These diagnostics do not claim a fix, increase the deadline or change production behavior.
